# NAS 素材协作架构

## 0.3.0 实现范围

Windows 客户端负责界面、目录扫描、缩略图、索引和同步；NAS 只存储原始媒体、协作事件及安装包。当前共享的业务数据是素材索引变更，工单、脚本和识别结果还未进入实现阶段。

## 数据流程

1. 扫描器流式枚举素材根目录，用规范化根目录和相对路径生成素材 ID，用路径、大小和修改时间生成变更指纹。该指纹不是整个文件的内容哈希。
2. 每批最多 50 条记录，在同一笔本地 SQLite 事务中写入素材变更与 outbox。数据库使用本地 WAL，事务中不写 NAS。
3. 同步器将 outbox 写入 NAS 的 `events/<节点 ID>/<事件 ID>.json`。先写唯一暂存文件，刷新后重命名；同 ID 已存在且内容不同则拒绝覆盖。写入成功后才确认本地发送状态。
4. 其他客户端按已接收事件 ID 去重，验证相对路径和素材 ID，再从自己的素材根目录检查文件最新状态并更新本地索引。不可访问的记录延后重试；损坏事件记入本地拒绝记录。
5. 界面只查询本地数据库并分页加载，后台通过消息队列交付扫描、同步和缩略图结果。图片与视频缩略图保存在每台电脑本地，生成并发上限为 2。

节点之间没有常驻协调服务器，也不通过 SMB 共享 SQLite 写锁。每台电脑首次运行生成独立节点 ID；共享事件可以用于另一台电脑重建索引，但当前没有事件压缩、共享快照或任务认领机制。

## 持久化位置

```text
\\SmartStorage\新媒体-137964276\
  素材库\                         原始媒体
  素材协作数据\events\<节点 ID>\   不可变索引变更事件
  软件库\素材协作\                安装包和 manifest.json

%APPDATA%\素材协作\settings.json  节点和目录配置
%LOCALAPPDATA%\素材协作\
  index.sqlite3                   索引、outbox/inbox、任务和重试状态
  thumbnails\                     本地图片和视频缩略图
  updates\                        下载并校验的安装包
```

## 失败与增长边界

已提交的扫描批次在暂停、断网或后续目录失败后保留。继续扫描会重新枚举目录，但不重复提交未变化素材。缺失或无权限访问的目录不会清空已有索引。收到旧事件时重新读取媒体的当前属性，避免用过时的文件属性覆盖新观察。

扫描和缩略图不修改原始媒体；读取媒体仍然消耗网络、磁盘与 CPU 资源。分页、流式扫描和限制缩略图并发控制单次工作量，但当前同步仍需枚举历史事件，日志总量会持续增长。大规模长期使用前还需要增量目录追踪、快照和压缩策略、删除与重命名协议、节点任务分配及多电脑长期压力验证。

## 发布与更新

`build.ps1` 从主程序提取版本，以独立版本目录构建。`-PublishOnly` 上传已有安装包，便于先测试后发布；同版本不同哈希的安装包不可覆盖。

发布目录保存 `素材协作-<版本>-setup.exe` 和 `manifest.json`。清单包含 `version`、`url`、`sha256`、`mandatory`、`notes`。发布先完成安装包复制与校验，再替换清单，因此复制失败不会将新版本暴露为可更新版本。

客户端按配置的发布目录和经过验证的版本生成安装包路径，复制到本地并校验 SHA-256，然后提示用户运行安装器。清单里的 `url` 不作为任意下载地址使用。当前更新为手动确认，`mandatory` 不强制安装，也未加入代码签名验证。

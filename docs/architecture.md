# NAS 素材协作架构

## 0.7.1 实现范围

Windows 客户端负责界面、目录扫描、缩略图、索引、播放、分类、脚本和工单；NAS 只存储原始媒体、协作事件及安装包。共享业务数据包括素材索引、分类及归类关系、脚本正文、工单内容、负责人、状态和素材绑定。语音和画面识别尚未实现。

## 数据流程

1. 扫描器流式枚举素材根目录，用规范化根目录和相对路径生成素材 ID，用路径、大小和修改时间生成变更指纹。该指纹不是整个文件的内容哈希。
2. 每批最多 50 条记录，在同一笔本地 SQLite 事务中写入素材变更与 outbox。数据库使用本地 WAL，事务中不写 NAS。
3. 同步器将 outbox 写入 NAS 的 `events/<节点 ID>/<事件 ID>.json`。先写唯一暂存文件，刷新后重命名；同 ID 已存在且内容不同则拒绝覆盖。写入成功后才确认本地发送状态。
4. 其他客户端按已接收事件 ID 去重，验证相对路径和素材 ID，再从自己的素材根目录检查文件最新状态并更新本地索引。不可访问的记录延后重试；损坏事件记入本地拒绝记录。
5. 界面只查询本地数据库并分页加载，后台通过消息队列交付扫描、同步和缩略图结果。图片与视频缩略图保存在每台电脑本地，生成并发上限为 2。

节点之间没有常驻协调服务器，也不通过 SMB 共享 SQLite 写锁。每台电脑首次运行生成独立节点 ID；共享事件可以用于另一台电脑重建索引，但当前没有事件压缩、共享快照或任务认领机制。

## 脚本、工单与版本同步

`collaboration_store.py` 为每个素材库保存独立记录。每次保存生成包含完整业务字段、父版本集合和内容哈希的不可变版本，同时在同一 SQLite 事务中写入 outbox。接收端在同一事务中写入版本和 inbox，失败可以重试。

版本之间以父子关系确定当前版本，不依赖各台电脑的时钟排序。收到子版本后再收到父版本仍得到同一结果。两个节点离线修改同一版本后，两个分支都保留；列表使用稳定的代表版本显示，并标注有并行版本。编辑者必须读取并比较版本，明确合并所有当前分支后保存。保存时在写事务内核对编辑器持有的版本集合，防止陈旧编辑覆盖已收到的更新。

素材以 ID 绑定，原片不复制、不移动。并行归档不会从列表隐藏仍有未归档分支的记录。显示名与负责人不用于鉴权，访问范围由 SMB 权限决定。

0.3.x 曾对未知类型事件标记已读，因此升级到 0.4.0 时每个素材库重放一次已读事件，找回旧版忽略的协作记录。之后未知事件保留原文，供后续升级使用。

## 分类与归类关系

`category_store.py` 保存分类名称、颜色、归档状态和不可变版本。名称修改依照父版本关系合并；并发版本保留，归档不会隐藏另一个尚未归档的分支。素材与分类为多对多关系，独立于媒体文件路径和文件内容。

归类使用 observed-remove set：新增产生独立标签，移除只引用已观察的新增标签，因此先收到移除再收到新增仍得到相同结果，未观察到的并发新增会保留。批量归类在同一事务内验证素材库归属、修改关系与写入 outbox，每次最多 1000 个素材/分类组合。接收端在同一事务内更新关系和 inbox。

本地 SQL 在分页前组合分类、未分类、文本和媒体类型条件；计数、分页记录及批量分类信息来自同一读取事务。分类数量只统计当前库本地已索引素材。0.5.0 升级先从本地保留的未知事件恢复分类，再重放一次共享事件，补回旧客户端曾忽略的分类。

## 按脚本整理

`organizer.py` 在客户端解析脚本分段，通过本地索引匹配文件名、相对路径和已有分类。候选包含证据与排序值，排序值不代表画面识别概率。脚本既有绑定可作为人工复用候选，不能作为某段画面匹配的证据。匹配阶段不改数据库，不读取 NAS 原片；候选数量受限，人工搜索分页补选。

应用前检查脚本版本、当前素材库归属、分类名称和批量上限。分类创建、归类添加、脚本绑定合并及 outbox 在同一 SQLite 写事务内完成，仍使用现有分类和脚本事件格式。新增绑定取并集，归类仅添加，避免替换其他协作者的已有内容。脚本快照过期或存在并行分支时拒绝应用，先处理脚本版本后重新制定方案。

整理窗口在主窗口预览导航时保留，UI 通过工作队列获取本地查询结果；未保存的脚本与整理选择在关闭时提示，写入期间禁止退出。

Word `.docx` 导入使用标准库读取 OOXML 正文与样式，在本机后台完成，不依赖 Office。正文与表格按文档顺序转换为文字，标题优先读取标题样式，其次文档属性及文件名；导入仅填写新的编辑草稿。文件、XML 与正文长度限制在读取和保存前执行，不访问外部关系，不提取嵌入对象。导入失败或读取期间草稿被修改时保留现有内容。

候选可按每批 20 项继续加载，后续页由 SQLite 在只读快照内计数和排序，并只返回当前页，避免在 Python 中累积排序前缀。整理窗口为每组单独记录匹配偏移、关键词快照、勾选及查看位置；手动补选不占匹配分页偏移。关键词改变后拒绝接收旧查询结果。加载更多和脚本文本视图切换本身不写入协作数据。

带编号和时间范围的拍摄脚本优先按这些标题分组，内部镜头说明与人物台词不触发新分组。时间范围、动作、对白和前置信息由完整正文派生；保存与同步继续使用原有脚本正文格式，另一节点可重建同样分镜。全部分镜原文拼接仍等于完整正文，前置信息不生成独立分类。匹配关键词优先显式关键词和镜头动作，素材匹配仍只基于本地索引元数据。

## 持久化位置

```text
\\SmartStorage\新媒体-137964276\
  素材库\                         原始媒体
  素材协作数据\events\<节点 ID>\   不可变素材和协作版本事件
  软件库\素材协作\                安装包和 manifest.json

%APPDATA%\素材协作\settings.json  节点和目录配置
%LOCALAPPDATA%\素材协作\
  index.sqlite3                   索引、分类、脚本/工单版本、outbox/inbox 和任务状态
  thumbnails\                     本地图片和视频缩略图
  updates\                        下载并校验的安装包
```

## 失败与增长边界

已提交的扫描批次在暂停、断网或后续目录失败后保留。继续扫描会重新枚举目录，但不重复提交未变化素材。缺失或无权限访问的目录不会清空已有索引。收到旧事件时重新读取媒体的当前属性，避免用过时的文件属性覆盖新观察。

扫描和缩略图不修改原始媒体；读取媒体仍然消耗网络、磁盘与 CPU 资源。分页、流式扫描和限制缩略图并发控制单次工作量，但当前同步仍需枚举历史事件，日志总量会持续增长。大规模长期使用前还需要增量目录追踪、快照和压缩策略、删除与重命名协议、节点任务分配及多电脑长期压力验证。

## 发布与更新

`build.ps1` 从主程序提取版本，以独立版本目录构建。`-PublishOnly` 上传已有安装包，便于先测试后发布；同版本不同哈希的安装包不可覆盖。

发布目录保存 `素材协作-<版本>-setup.exe` 和 `manifest.json`。清单包含 `version`、`url`、`sha256`、`mandatory`、`notes`。发布先完成安装包复制与校验，再替换清单，因此复制失败不会将新版本暴露为可更新版本。

客户端按配置的发布目录和经过验证的版本生成安装包路径，复制到本地并校验 SHA-256，然后提示用户运行安装器。清单里的 `url` 不作为任意下载地址使用。当前更新为手动确认，`mandatory` 不强制安装，也未加入代码签名验证。
